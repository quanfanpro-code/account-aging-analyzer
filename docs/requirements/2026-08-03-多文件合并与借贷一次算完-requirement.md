# 需求：序时账多文件合并 + 借贷双方一次算完

日期：2026-08-03
项目：往来账龄分析工具
状态：已评审（2026-08-03），调研摘要逐条对照代码核实属实，仅三处小修补

## 一、背景与问题

当前工具有两个使用痛点：

1. **多年序时账要手动合并**：工具一次只接受一个序时账文件。审计时若要算多年累计账龄，用户得自己把多个年度的序时账手动粘贴合并成一个 Excel，费时且容易出错。

2. **借方贷方科目要分两遍跑**：工具每次运行只能选一个余额方向（借方或贷方）。借方类科目（应收、预付、其他应收）和贷方类科目（应付、预收、其他应付）要分两遍导入、两遍计算、两遍导出，操作繁琐。

## 二、用户与使用场景

- **用户**：审计人员，无编程背景，在界面上操作。
- **场景一**：拿到 2023、2024、2025 三个年度的序时账文件，想合并后一次算出截止 2025 年底的账龄。
- **场景二**：一份期初余额表里同时有应收类和应付类科目，想一次算完两类，不用跑两遍。
- **场景三**（老用户兼容）：只有单年度序时账、只有借方科目，操作方式和现在一样。

## 三、功能范围

### 功能一：序时账多文件合并

1. 序时账的"选择文件"改为支持多选（按住 Ctrl 选多个文件）。
2. 每个文件分别用现有的列名智能匹配（ColumnMapper）自动识别列名。
3. 必要字段（日期、科目编码、明细名称、借方金额、贷方金额）匹配不上的，报错提示是哪个文件缺哪列，让用户自行清理数据。
4. 全部文件必要字段都匹配上后，按统一标准列名拼接成一个数据集，后续流程不变。
5. 列映射界面基于第一个文件展示，和现在一样。后续文件用相同匹配规则自动处理，用户无需逐个调整。
6. 预览区显示合并后的数据（前 10 行）和"已合并 N 个文件"的提示。
7. 期初余额表不支持多文件（期初是单一时点快照，一个文件即可）。

### 功能二：借贷双方一次算完

1. **方向判断**改为每个科目自动判断（判断粒度：科目编码级，同一科目下所有明细共用同一个方向），综合三个维度（按优先级降序）：
   - **第一优先：期初余额方向**。该科目编码下，期初余额表里借方余额合计 vs 贷方余额合计，哪个大就用哪个方向。两者相等或科目不在期初表里，进入下一步。
   - **第二优先：科目编码首位**。1 开头（资产类往来）-> 借方；2 开头（负债类往来）-> 贷方。其他首位进入下一步。
   - **第三优先：科目名称关键词**。名称含"应收""预付""其他应收"等 -> 借方；含"应付""预收""其他应付"等 -> 贷方。匹配不上进入下一步。
   - **兜底：默认方向**。以上都判断不了，用界面上选的默认方向。
   - 三个维度能自动覆盖整科目反挂场景（余额方向最直接，编码和名称作辅助）。
2. 界面"余额方向"单选按钮文案改为"默认方向（识别不了的科目用）"，保留借方/贷方两个选项，作为兜底。
3. 计算引擎准备借方、贷方两个实例，按每个科目的判断结果分给对应引擎。
4. 期初余额按对应口径计算（借方类 = 借 - 贷；贷方类 = 贷 - 借）。
5. 期初分档校验（分档合计对账）两个方向都照常生效。
6. 计算日志里打出每个科目判断出的方向及依据（余额/编码/名称/默认），方便用户检查。
7. 报告导出：账龄汇总表按方向分两个 sheet（"借方账龄汇总表"、"贷方账龄汇总表"），各自独立合计。其他 sheet（逐笔追溯明细、期初余额验证、期末余额验证、参数说明）保持原有结构，内容含两个方向的结果。
8. 报告"参数说明" sheet 中的"余额方向"参数行，文案同步改为"默认方向"。

## 四、明确不做

- **不做例外清单**：靠三维度自动判断 + 默认方向兜底，不在界面上加手动指定方向的例外清单。
- **不做文件间自动去重**：若用户重复导入了同一笔凭证，工具不去重。可在日志中提示可能重复的记录数，但不自动删除。
- **不做期初余额多文件**：期初余额只接受一个文件。
- **不改引擎核心 FIFO 逻辑**：引擎的先进先出核销算法不动。
- **不做明细级方向判断**：同一科目编码下所有明细共用一个方向（已决策，见风险表）。

## 五、约束与风险

| 风险                 | 说明                                                         | 对策                                                         |
| -------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 三维度都判断不了     | 科目编码非 1/2 开头、名称无关键词、期初余额为 0 或不在表里   | 用默认方向兜底；日志打出判断依据供检查                       |
| 整个科目反挂         | 如预收挂在应收编码下                                         | 期初余额方向能自动识别（贷方合计 > 借方合计 -> 贷方）        |
| 同科目下部分明细反挂 | 如应收账款下某客户是贷方余额（预收性质），科目级判断按净额定方向，该明细的反挂会被"吞"掉 | 已决策接受此限制（选择科目级粒度）；该明细余额会按负余额单列展示，仍可在报告中看到 |
| 多文件列名不一致     | 不同年份文件列名可能不同                                     | 用列名智能匹配自动对应；必要列匹配不上则报错                 |
| 借贷合计混加         | 当前汇总表合计行把所有科目混加                               | 报告分两个 sheet，各自独立合计                               |

## 六、验收标准

1. 能选择多个序时账 Excel 文件，工具自动合并成一个数据集并计算。
2. 列名不一致的文件，工具能自动识别必要列；匹配不上的会报错提示具体文件和缺失列。
3. 同一次计算能同时算出借方科目和贷方科目的账龄，结果正确。
4. 导出的 Excel 报告中，账龄汇总表分为"借方账龄汇总表"和"贷方账龄汇总表"两个 sheet，各自有独立合计。
5. 计算日志能看到每个科目判断出的方向及依据（余额/编码/名称/默认）。
6. 老用户单文件、且数据里只有借方类科目时（默认方向选借方），计算结果与改造前一致。
7. 期初分档校验在两个方向下都正常生效。
8. 整科目反挂（如预收挂在应收编码下）能被期初余额方向自动识别为贷方。

## 七、调研摘要与来源

以下结论已于 2026-08-03 逐条对照代码核实：

- 代码现状：方向（direction）是全局开关，从界面 step_config -> step_result -> orchestrator -> fifo_engine 一路传递，一趟计算所有科目用同一口径。（已核实，涉及 7 个文件）
- 科目编码格式：模拟数据用一级编码（1122 应收账款、2202 应付账款），首位 1/2 可区分借贷方向。
- 期初余额表已有"借方余额"和"贷方余额"两列，可直接用作方向判断的第一优先信号。（已核实，column_mapper.py 的 balance 必填字段即含这两列）
- 结果对象：AgingResult 已有 direction 字段，报告层可据此分边呈现。（已核实，fifo_engine.py 返回时写入）
- 期末余额验证表已有"方向"列，无需新增。（已核实，report.py 第 150 行）
- 引擎核心（FIFOEngine.calculate）接收 direction 参数，借贷两种口径的算法都支持，不用改核心逻辑。（已核实）
- 列名智能匹配（ColumnMapper.auto_map）已支持长词优先匹配，多文件可复用；必填字段清单与本文档一致（序时账：日期、科目编码、明细名称、借方金额、贷方金额）。（已核实，column_mapper.py）
- 报告当前为 5 个 sheet：账龄汇总表、逐笔追溯明细、期初余额验证、期末余额验证、参数说明，与本文档描述一致。（已核实，report.py）
- 文件选择对话框当前为单选（askopenfilename），改多选（askopenfilenames）为标准操作。（已核实，step_import.py 第 114 行）
- 计算页已有日志框，逐科目输出方向判断依据可行。（已核实，step_result.py）
