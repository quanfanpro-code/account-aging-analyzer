# 暂估转科目FIFO设计（替代原单据匹配方案）

## 决定
复用现有FIFO余额层。暂估与正式往来归入同一单位和类别后，按流水顺序承接内部流量；不单独建立单据匹配、存货批次或价税识别系统。单据一一对应方案已由用户取消；统一改为FIFO。把全部余额统一改成一个日期不能保留多批账龄，不采用。

## 数据流
全层级暂估与名称预检 → 用户确认 → 保留原科目和暂估标志并归集 → 截止日前按日期和同日原行序FIFO承接 → 原发生额计算余额、扣除等额内部流量后运行现有FIFO → 反向重分类 → 成对对抵 → 唯一最终账龄。
承接模块只标记等额内部借贷流量，原发生额不删除；因此原余额层、开账日期及分档继续使用主FIFO引擎。报告记录承接金额和FIFO规则，凭证仅作为可选来源信息。

## 边界
同一单位和归集类别内承接，不处理空单位；实际收付、退货退款不参与内部流量。正式转入从冲估同月及后续发生额按FIFO取得，更早月份的旧正式业务不作为转入。两边都须在截止日前。正式转回暂估须明确转暂估。剩余未承接流量正常核销或增加。不读取采购单、发票、物料或税额字段。

## 验证与回滚
26项承接测试覆盖八类×两种层级、两批余额、不同流水条数、无单据字段、部分红字、真实收付、跨日期截止日、不同单位、期初反向余额。全套182项验证。原源码与本地未提交版本已按宿主规则备份，用后续纠正提交替代a95c046，不改写远端历史。
