# 需求：往来账龄分析全自动化改造

- 日期：2026-08-25
- 状态：阶段 1 已批准
- 项目：往来账龄分析工具

## 一、背景与问题

当前程序在实际使用中存在以下问题：

1. 未导入期初余额时，程序虽然已按期初余额为 0 计算，但配置页仍显示并预填期初余额日期，造成仍需填写期初时点的误解。
2. Excel 可能包含多个工作表，现有程序固定读取第一个工作表，无法由用户指定实际数据表。
3. 期初余额表和序时账可能包含全部会计科目，现有程序没有先筛选往来科目，其他科目会进入账龄计算范围。
4. 核心计算已能识别借方和贷方往来，但配置页仍要求选择默认借方或贷方，容易让用户误以为两类往来必须分两次运行。
5. 账龄汇总表在账龄名称留空时会生成空白表头，且“负余额”的名称和含义不直观。

本次改造的目标是：一次导入一个文件、明确选择工作表、自动筛选八类往来、自动按固定方向同时计算借方和贷方账龄，并确保导出表头与配置界面完全一致。

## 二、用户与使用场景

主要用户为需要编制往来账龄分析和审计底稿的财务、审计人员。

典型场景：

1. 只有序时账，没有期初余额，期初余额应视为 0。
2. 期初余额文件或序时账文件包含多个工作表，需要明确选择实际数据表。
3. 输入文件为全科目数据，需要只保留八类往来本金。
4. 同一份数据同时包含资产类和负债类往来，需要一次计算并分别汇总。
5. 用户自定义账龄区间和名称，导出表头必须与配置页逐项一致。

## 三、术语与业务口径

### 3.1 八类往来

借方类往来：

1. 应收账款
2. 预付账款
3. 其他应收款
4. 合同资产

贷方类往来：

1. 应付账款
2. 预收账款
3. 其他应付款
4. 合同负债

### 3.2 反向余额

反向余额是指余额方向与科目正常方向相反：

- 借方类往来出现贷方余额；
- 贷方类往来出现借方余额。

反向余额不改变科目所属汇总表，单独列入“反向余额（待核对）”，并以负数列示。

### 3.3 账龄名称

账龄名称是配置页每个账龄区间对应的导出表头。账龄名称必须非空、不得重复，导出时必须按照配置页显示的数量、顺序和名称原样使用。

## 四、功能范围

### 4.1 文件和工作表选择

1. 期初余额文件仍为可选；序时账文件为必选。
2. 期初余额文件和序时账文件均一次只能选择一个 Excel 文件，不支持一次选择多个文件。
3. 文件只有一个工作表时，程序自动选择并读取该工作表。
4. 文件有多个工作表时，程序不得默认选择第一个，必须由用户在页面中明确选择一个工作表后才能继续。
5. 切换工作表后，程序必须重新加载预览、自动列映射和账龄分档检测，不得沿用前一个工作表的旧状态。
6. 自动列映射后仍允许用户手动调整；必要字段未映射时，点击“下一步”必须列出缺失字段并禁止继续。

### 4.2 期初余额和日期

1. 未选择期初余额文件时，期初余额按 0 计算。
2. 未选择期初余额文件时，期初余额日期输入框保留但置灰，显示“无期初余额，无需填写”，共享状态中的期初日期必须为 `None`。
3. 选择期初余额文件后，期初余额日期必须填写，并且必须早于计算截止日期。
4. 程序不得在有期初余额但未填写日期时替用户猜测期初时点。

### 4.3 八类往来识别和过滤

1. 期初余额表和序时账采用同一套过滤规则，只保留八类往来本金，其他科目全部忽略。
2. 以科目名称为主要识别依据：科目名称中包含八类标准名称之一即可识别，允许名称带编码、层级或其他前后缀。
3. 常见科目编码仅作辅助识别。名称为空或无法识别时，可按常见编码前缀识别：`1122`、`1123`、`1221`、`1486`、`2202`、`2203`、`2241`、`2204`。
4. 科目名称与编码分类冲突时，以科目名称为准，并在日志中记录警告。
5. 即使名称包含八类标准名称，只要同时包含“坏账准备”或“减值准备”，也必须排除。
6. 八类往来中的明细名称为空时，不得丢弃金额，统一归入“（未填明细）”继续计算。
7. 同一个科目编码在期初余额表、序时账或不同明细中被识别为两个及以上往来类别时，程序必须停止计算，并列出冲突编码、识别出的类别、原科目名称和来源工作表；不得自动选择其中一类。
8. 如果过滤后没有任何八类往来数据，程序必须明确提示并停止计算，不得生成看似成功的空结果。

### 4.4 过滤日志

期初余额表和序时账分别记录：

1. 原始行数；
2. 保留行数；
3. 忽略行数；
4. 八类往来各自保留行数；
5. 明细名称为空并归入“（未填明细）”的行数和金额；其中期初余额表分别列示借方余额、贷方余额合计，序时账分别列示借方金额、贷方金额合计；
6. 科目名称与编码冲突的警告。

日志不逐行输出被忽略数据，避免大量数据刷屏。

### 4.5 借贷方向和一次计算

1. 删除配置页的借方、贷方默认方向选择。
2. 科目方向按八类往来固定，不再根据期初余额大小把整个科目改判到另一方向：
   - 应收账款、预付账款、其他应收款、合同资产固定为借方类；
   - 应付账款、预收账款、其他应付款、合同负债固定为贷方类。
3. 一次计算同时处理借方类和贷方类往来。
4. 导出文件始终保留“借方账龄汇总表”和“贷方账龄汇总表”。某一方向没有数据时，对应工作表仍保留并标注“无数据”。

### 4.6 账龄区间和账龄名称

1. 配置页原“显示别名”改为“账龄名称”。
2. 每个账龄区间必须有非空且唯一的账龄名称。
3. 默认名称根据区间上下限自动生成，并随上下限修改自动更新，例如区间从 0—90 天改为 0—120 天时，默认名称同步改为“0-120天”。
4. 上限为 9999 天的最后一档，默认名称使用“下限天以上”，例如“730天以上”。
5. 用户可以手动修改账龄名称；手动名称非空且唯一时予以保留。
6. 导出汇总表的账龄列数量、顺序和名称必须与配置页最终显示完全一致。
7. 现有账龄区间连续性、上下限合法性和边界点归前档规则保持不变。

### 4.7 汇总表和反向余额

1. 借方和贷方账龄汇总表始终保留“反向余额（待核对）”列，无反向余额时显示 0。
2. 反向余额继续以负数列示。
3. 每行满足“各账龄档位合计＋反向余额＝合计”。
4. 参数说明工作表必须说明：借方类出现贷方余额、贷方类出现借方余额时，金额列入“反向余额（待核对）”，不进入普通账龄档位。

## 五、明确不做

1. 不支持一次选择或合并多个序时账文件。
2. 不自动合并同一工作簿中的多个工作表。
3. 多工作表时不自动猜测应处理哪个工作表。
4. 不把坏账准备、减值准备或八类往来以外的科目纳入计算。
5. 不修改现有先进先出计算口径、账龄边界规则和截止日后交易剔除规则。
6. 不新增第三方依赖。
7. 不在开发或验收中途提交、推送；本轮用户已明确授权在全部验收通过并更新 README 后创建提交并推送当前分支。仍不执行合并、创建拉取请求或删除操作。

## 六、约束与风险

1. 仅面向 Windows 使用环境。
2. 修改现有文件前必须先备份到项目目录之外的 `BackUp` 文件夹，并保留原文件名。
3. 当前工作区已有 `src/gui/step_result.py` 的未提交修改，实施时必须原样保留，不得覆盖。
4. 科目编码可能因企业会计科目表不同而变化，因此科目名称优先，编码只作辅助。
5. 工作表切换后若未清空旧映射，可能把旧列名错误应用到新数据，必须用测试覆盖状态重置。
6. 过滤全科目数据会主动忽略大量记录，必须用日志留痕，避免用户误以为数据被遗漏。
7. 固定科目方向后，反向余额必须留在原科目类别中，不能被自动转入另一张汇总表。
8. 同一科目编码出现多个往来类别通常表示列映射、工作表选择或源数据不一致，自动继续会混合不同业务类别，因此必须设置硬停止门禁。

## 七、验收标准

1. 只选择一个序时账文件、不选择期初余额文件时，可以完成计算；期初余额为 0，期初日期输入框置灰且状态为 `None`。
2. 单工作表文件自动读取；多工作表文件必须手动选择后才能继续，期初余额和序时账均适用。
3. 切换工作表后，预览、列映射和期初分档检测同步更新，旧工作表状态不残留。
4. 同时含八类往来、非往来科目、坏账准备和减值准备的数据中，只保留八类往来本金。
5. 名称带前后缀的八类往来可以识别；名称与编码冲突时按名称分类并记录警告。
6. 同一科目编码在不同来源或明细中被识别为不同往来类别时，计算停止，提示信息能定位编码、名称、类别和来源工作表。
7. 合同资产进入借方账龄汇总表，合同负债进入贷方账龄汇总表。
8. 应收账款出现贷方余额时，仍留在借方账龄汇总表，并以负数进入“反向余额（待核对）”；贷方类反向余额同理。
9. 明细名称为空的八类往来金额统一归入“（未填明细）”，日志记录行数和金额。
10. 配置页所有账龄名称非空、唯一；默认名称随上下限更新；最后一档默认显示“下限天以上”；手动名称可以保留。
11. 两张汇总表的账龄列与配置页在数量、顺序和名称上逐项一致，不出现空白表头。
12. 借方和贷方两张汇总表始终存在，无数据方向显示“无数据”；“反向余额（待核对）”列始终存在。
13. 日志分别显示期初余额表和序时账的原始、保留、忽略行数，以及八类往来分项数量。
14. 现有有期初和无期初计算、先进先出、日期清洗、期后交易剔除及 Excel 导出行为不发生回归。
15. 所有新增行为先有正确失败的测试，再做最小实现；最终运行完整测试、语法检查、端到端导出和实际 Excel 表头验收。

## 八、调研摘要与来源

本阶段未使用外部资料，结论来自用户确认和项目当前代码的只读检查：

1. `src/gui/step_import.py` 当前允许一次多选序时账文件，并固定读取每个文件的第一个工作表。
2. `src/gui/step_config.py` 当前始终预填期初余额日期，并保留默认借方、贷方选择。
3. `src/core/direction_resolver.py` 和 `src/core/orchestrator.py` 已具备一次运行两种方向的基础，但现有方向优先受期初余额大小影响。
4. `src/core/report.py` 在收到与区间数量相同的空名称列表时会直接生成空白账龄表头；现有“负余额”列仅在出现反向余额时生成。
5. 当前完整自动化测试基线为 94 项通过；该结果仅代表改动前基线，不代表本次新需求已经实现。
