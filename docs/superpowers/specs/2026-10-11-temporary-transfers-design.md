# 暂估连续账龄设计

## 方案比较
选择在同一单位、同一归集科目的FIFO队列中抵消已证明内部转科目的等额两腿：复用全部原采购或销售批次，原借贷列独立保留。另一方案为分别计算暂估和正式科目的队列再搬运层，会引入重复核销和队列同步；第三种将正式余额统一改成最早日期会丢失多批次，不能满足需求。

## 数据流
原始整表 → 全层级暂估与名称预检 → 用户归属及名称确认 → 从同凭证完整行补充业务单号 → 保留原科目、编码及暂估标志 → 归入正常科目 → 截止日前匹配内部转科目 → 原发生额计算原账余额、扣除转科目等额两腿计算FIFO → 反向重分类 → 成对对抵 → 唯一最终账龄。
下级暂估分支以具体编码确认；独立暂估一级科目按一级编码确认。库存等同凭证行只用于补充业务单号证据，不参与往来余额。

## 边界和错误处理
必须逐单位匹配，不跨主体；空明细不匹配。退货、退款、真实现金收付不冒认为转账。优先相同业务单号，允许跨日期且两边均已入账；其次同凭证明示冲暂估。不能只凭金额或名称相近认定。匹配共同金额，非对应差额继续按原发生额处理；不假设税率。缺少证据保留原处理。FIFO校验抵消借贷平衡、标记不得超过该行发生额，错误即停止。

## 验证与回滚
八类×两种层级、多批次及实际核销、红字、部分转账、退货、截止日后记录、报告证据页。再运行全套既有测试。备份原源码和成品，Git提交记录可回退。归属和名称决策仍限定为当前输入资料。
